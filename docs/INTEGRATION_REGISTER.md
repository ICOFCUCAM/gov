# CivicOS — Integration Register

Everything in the platform that is built but still runs on a placeholder,
a demo value or an in-memory stand-in, and what it takes to connect it for
real. Keep this file current: **any change that adds a stub, a placeholder,
a demo value, a new external dependency or an integration point adds or
updates an entry here in the same change** (see `CLAUDE.md`).

Status: **Ready** = works for real once configured · **Partial** = real for
some cases · **Placeholder** = shaped correctly, not connected.

Last reviewed: 17 Oct 2026.

---

## 1. Platform and data

**One owner per register** (architecture review R19): each register has one authoritative store and one write API; every other copy is a mirror, a fallback used only when the owner is unreachable, or retired (kept reachable, never written). The decision is code, `app/src/lib/data/register-owners.ts` (served at `GET /api/platform/owners`); `register-owners.test.ts` fails when a new platform store or civic-api module has no owner. Summary: the platform stores own the nation profile, institutions, the platform audit chain, permits, payments, operations, federation, officials, the twin, facilities, boundaries, case loads, public sites and the Update Center; the substrate owns directives (platform copy as fallback), the citizen runtime, identity, telemetry and its own audit trail; every `services/civic-api` module is retired (no app route calls it).

Not yet: per-route request rates and latencies (golden signals) — the middleware runs at the edge and cannot count into the Node process; an OpenTelemetry collector in the deployment can take them from the ingress.

**Traces** (review R12, O2): OpenTelemetry, off by default. With `CIVICOS_OTEL_ENDPOINT` (the nation's own collector, OTLP/HTTP; optional `CIVICOS_OTEL_HEADERS`, `CIVICOS_OTEL_SERVICE_NAME`, `CIVICOS_OTEL_SAMPLE_RATIO`) `src/instrumentation.ts` registers a tracer provider (`app/src/lib/ops/otel.ts`, official `@opentelemetry/*` SDK packages, a small OTLP/JSON exporter of our own with no gRPC/protobuf dependency). Next.js then adds spans for every request and API route handler (an incoming W3C `traceparent` from the ingress is honoured); `lib/ops/trace.ts` adds `outbound.fetch` (every `safeFetchText`, host and method only), `state.save` (each store a persistence flush writes; a one-line wrap in `persist.ts`) and `audit.append` (each audit entry, sequence and action). Log lines written inside a span carry `traceId` and `spanId`; route handlers tag their span with the `x-request-id` (`civicos.request_id`). Attributes with sensitive names are redacted and query strings cut before export. Nothing is sent anywhere else: this is not an operational-data category of `lib/data/sovereignty.ts` (those go to the publisher, through `transmit()`). Compose: `otel-collector` in the observability profile (`infra/docker/otel-collector.yaml`, traces kept in a file on the host); Helm: `otel.enabled`, `otel.collector.enabled` (collector Deployment, Service, network policy) or `otel.endpoint` for an existing one. To connect: point the collector's exporters at the nation's own trace backend (Jaeger, Tempo, OpenSearch). `/api/health` says whether tracing is on.

**Rate limits** (review S9): `app/src/lib/ops/rate-limit.ts`, token buckets per official account (else client address) and scope — upload 6/min (boundary files, district packs, site imports), check 120/min (location checks), write 120/min, public 60/min — answering 429 with Retry-After and RateLimit headers. The upload and check routes apply their scope themselves; the middleware applies `write` to every other change through the API and `public` to the citizens' email-update requests (`lib/ops/rate-limit-core.ts`, shared by both), leaving machine callers limited by their own credential (integration and feed keys' `rateLimitRpm`, cron and agent secrets) as they were. Buckets are in the server's memory (several instances would each count separately). **At the ingress:** Helm `ingress.limits` sets ingress-nginx `limit-rps` (with a burst multiplier), `limit-connections` and `proxy-body-size` per client address for the whole site (20/s, 20 connections, 2 MB by default) and, as one Ingress per path group, tighter rates and their own body sizes for uploads (boundaries, district packs: 140 MB), imports (CSV runs, candidates, site imports, XLIFF: 25 MB) and the connected systems' feeds (5 MB); `limit-allowlist` for the nation's monitoring. Compose: the `edge` profile runs nginx with the same limits (`infra/docker/nginx-edge.conf`). To tune: set the rates to the nation's traffic after the first weeks; behind another proxy, make sure the client address reaches nginx (real-IP settings).

**Third-party code in the advisory feed** (review R2): the dependency audit's findings (`scripts/audit-deps.mjs --publish <publisher>`, run by CI when `CIVICOS_PUBLISHER_URL` is set) become interim advisories `CSA-DEP-<GHSA>` in the Update Center feed with their assessment and review date, and resolve as final when no longer reported (`importDependencyFindings`, `/api/releases/publisher/advisories/dependencies`), so the patch-time commitments cover dependencies. CI also scans the app container image (Trivy, high and critical, unfixed ignored) and keeps a CycloneDX SBOM.

**Soak test** (review R17): `npm run soak` (`SOAK_SCALE`, budgets `SOAK_FLUSH_S`, `SOAK_QUERY_MS`, `SOAK_HEAP_MB`) loads twin observations, facility register sites and audit entries to national scale and measures saving, heap and queries. Baseline at scale 0.25 (50k observations, 5k sites, 29k audit entries), before the spatial index and archive work: sites load 19.0 s (grows faster than linearly: duplicate checks scan every site), first save 0.35 s and 21 MB of snapshot, an unchanged save still 0.22 s (every store re-encoded to detect change), heap 213 MB, as-of query 3 ms. After the review work (spatial index, archive, metric registry, quiet save ticks): sites load 6.6 s (2.9× faster), duplicate check 1 ms, first save 0.51 s, a forced unchanged save 0.16 s — and the save loop now skips encoding entirely while nothing is audited (full sweep every 60 s), heap 220 MB, as-of query 3 ms.
